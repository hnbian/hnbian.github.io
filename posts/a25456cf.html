第一眼看上去，我当时还以为是Scala 插件坏了或者代码里有语法问题,依赖冲突把编译搞挂了. 结果往下看才发现，这次问题其实很典型：不是代码问题，而是环境里的 javac 路径找错了。

一开始最容易被带偏的地方

这份日志其实挺会“误导人”的。

因为在真正报错前，前面已经出现了不少 warning，比如：

[WARNING] Unrecognised tag: 'blocked'

还有：

Expected all dependencies to require Scala version: 2.11.8
org.json4s:json4s-core_2.11:3.2.11 requires scala version: 2.11.0

以及：

a pure expression does nothing in statement position

如果排查经验不够，很容易顺着这些 warning 一路查下去，最后越查越远。

我一开始也差点被这些信息带偏，尤其是看到 scala-maven-plugin 报错的时候，第一反应就是：是不是 Scala 版本冲突了，或者某个 Scala 文件写挂了。

但这类问题最怕的就是——真正导致构建失败的，往往不是前面最花哨的 warning，而是最后那条最朴素的报错。

真正要盯住的是哪一行

这次最关键的一行其实是：

Cannot run program "D:\ProgramFiles\Java\jdk1.8.0_341\jre\bin\javac"

看到这里，问题基本就已经很明确了。

因为正常情况下，javac 应该在这里：

D:\ProgramFiles\Java\jdk1.8.0_341\bin\javac.exe

而不是这里：

D:\ProgramFiles\Java\jdk1.8.0_341\jre\bin\javac

也就是说，编译过程去找了一个 根本不存在的路径。

Windows 返回的 CreateProcess error=2 其实也已经把答案说得很直白了：

系统找不到指定的文件。

这时候就应该立刻把注意力从“代码有没有问题”切回到“环境是不是配错了”。

为什么 Scala 编译会去找 javac

这里还有一个很容易让人疑惑的点：

不是 Scala 项目吗，为什么会去调 javac？

看日志就明白了，这个项目不是纯 Scala：

  • 32 个 Scala 源文件
  • 2 个 Java 源文件

也就是说，这是一个 Scala + Java 混编项目。

scala-maven-plugin 在做增量编译的时候，会一起处理 Scala 和 Java 源码，所以它去调用 javac 是正常行为，不是异常行为。

换句话说，这次不是“插件莫名其妙找 javac”，而是：

它本来就该找，只不过找错地方了。

我最后是怎么定位到根因的

我后面重新顺着日志看了一遍，基本把问题归到这一类：

1. JAVA_HOME 很可能配错了

最常见的错误写法是：

JAVA_HOME=D:\ProgramFiles\Java\jdk1.8.0_341\jre

正确应该是：

JAVA_HOME=D:\ProgramFiles\Java\jdk1.8.0_341

只要把 JAVA_HOME 指到了 jre，很多构建工具在推断编译器路径的时候就可能出问题。

2. IDEA 内部跑 Maven 时，可能偷偷用了另一套 Java

这个也很常见。

有时候你命令行里的 java 和 javac 都没问题，但 IDEA 里一点 Maven Compile 还是挂。

原因是 IDEA 自己还有一套配置，比如：

  • Project SDK
  • Maven Runner JDK
  • Maven Importer JDK

只要其中某个地方配成了 JRE，就可能出现这种“命令行没事，IDEA 里死活不行”的情况。

这类问题最烦的地方就在这里：表面看像项目问题，实际上是 IDE 运行时环境和你想象的不一致。

3. 也不排除 JDK 安装本身就有问题

还有一种更直接的可能，就是这个文件本身就不存在：

D:\ProgramFiles\Java\jdk1.8.0_341\bin\javac.exe

如果连这个文件都没有，那就不是单纯的配置问题了，而是 JDK 安装不完整，或者装错了版本。

那前面的 warning 到底要不要管

要管，但要分优先级。

blocked 标签 warning

[WARNING] Unrecognised tag: 'blocked'

这个大概率是因为当前 Maven 版本太老，settings.xml 里却用了新配置项。

你这里用的是：

apache-maven-3.6.1

所以它认不出来这个标签，很正常。

但这个 warning 不会直接导致 javac 找不到。

Scala 版本不一致 warning

Expected all dependencies to require Scala version: 2.11.8
org.json4s:json4s-core_2.11:3.2.11 requires scala version: 2.11.0

这个说明依赖版本没有完全对齐，后面最好收敛一下，不然以后可能埋坑。

但就这次构建失败来说，它也不是主因。

a pure expression does nothing in statement position

这个属于代码 warning，通常表示某一行表达式写出来了，但实际上没有效果。

这种问题该修还是要修，不过它不会导致这次这种“连编译器进程都起不来”的失败。

我会怎么处理这个问题

如果下次我自己再碰到类似问题，我会直接按这个顺序查。

第一步：先确认 javac.exe 到底在不在

dir D:\ProgramFiles\Java\jdk1.8.0_341\bin\javac.exe

如果这个文件都不存在，那别折腾了，先重装 JDK。

第二步：检查环境变量

echo %JAVA_HOME%
where java
where javac
java -version
javac -version

重点看两件事：

  • JAVA_HOME 有没有指到 jre
  • where javac 找到的是不是你预期的那份 JDK

推荐配置应该是：

set JAVA_HOME=D:\ProgramFiles\Java\jdk1.8.0_341
set PATH=%JAVA_HOME%\bin;%PATH%

第三步：去 IDEA 里查 Maven 用的到底是谁

重点看：

  1. Project Structure -> Project SDK
  2. Settings -> Build Tools -> Maven -> Runner
  3. Settings -> Build Tools -> Maven -> Importing

全部都应该指向：

D:\ProgramFiles\Java\jdk1.8.0_341

不要指向：

D:\ProgramFiles\Java\jdk1.8.0_341\jre

第四步：再回过头清理 warning

比如：

  • 升级 Maven
  • 统一 Scala 依赖版本
  • 修掉无意义 expression warning

这些都值得做，但优先级一定排在“先让编译跑起来”之后。

这次踩坑最大的感受

这类报错特别像“假复杂问题”。

看起来日志一大堆：

  • Maven settings warning
  • Scala 版本 warning
  • Scala 代码 warning
  • 插件报错

很容易让人以为是个很深的依赖兼容问题。

但其实真正的根因很朴素：

构建环境把 javac 找到了 jre\bin 下面，而这个路径根本不对。

也就是说，这次不是业务代码翻车，不是 Scala 语法翻车，也不是依赖解析翻车，本质上还是 JDK / JRE 配置问题。

最终结论

这次编译失败的核心原因可以总结成一句话：

scala-maven-plugin 在执行 Scala/Java 混合增量编译时，需要调用 javac，但运行环境把 javac 错误定位到了 JDK\jre\bin 目录下，最终触发 CreateProcess error=2。

真正的修复重点也很明确：

  • 使用完整 JDK，而不是 JRE
  • JAVA_HOME 指向 JDK 根目录
  • PATH 中能找到正确的 javac
  • IDEA 里的 Maven Runner / Importer / Project SDK 都要确认一遍

这次排查时用到的命令

echo %JAVA_HOME%
where java
where javac
java -version
javac -version
dir D:\ProgramFiles\Java\jdk1.8.0_341\bin\javac.exe

总结

以后再看到这类错误，我会先提醒自己两件事：

  1. 不要先被一堆 warning 带偏
  2. 先看最后那条真正导致进程启动失败的报错

只要看到这种路径：

D:\ProgramFiles\Java\jdk1.8.0_341\jre\bin\javac

基本就该立刻想到：

不是 Scala 写挂了，而是 Java 环境配歪了。
